# ADR-001 · I1 core

As of 08.11.2026 Europe/Berlin. Decisions for the local prototype. No HTTP API and no product.

## Context

v0.2 fixes architecture, a process, and fifteen tests. Several business details remain open or draft only in the specification. This ADR records decisions taken. The draft text itself does not become implementation evidence.

## Decisions

1. Persistence is a local SQLite file. A transaction with `BEGIN IMMEDIATE` writes business state, audit, and receipt or none of them. There is no HTTP server, model adapter, or send adapter.
2. Only module `material-prep-1` is implemented. Other module profiles from v0.2 remain documentation. Another `module_id` is rejected instead of opening an agent path.
3. Canonicalization `canon-1`: UTF-8 JSON, keys sorted, separators without spaces, no NaN or Infinity, duplicate keys rejected on parse. Hash form `sha256:` plus hex. Timestamps stored only as `YYYY-MM-DDTHH:MM:SSZ`. Display in Europe/Berlin is derived, not storage form.
4. Source text stays character-faithful. `text_hash` hashed that text. `content_hash` hashed the canonical segment list. Derived statements normalized to NFC.
5. `correction_note` is not a replacement. Only explicit `replaces <source>` would withdraw a source. Without that, 20 and 24 stay a conflict. Silent preference for the later number is forbidden. A ruleset cannot disable this guard.
6. References bind additionally `content_hash`. That is not in A2’s minimum table and is needed so a tampered hash does not become fact approval.
7. `confirm_fact` is a local guard function in the application service, not the HTTP routes sketched in A4. It does not store an invalid confirmation. Route `POST /v1/runs/{id}/commands` does not exist.
8. Receipts apply per tenant id, operation, and idempotency key. An authorized actor of the same id may read the same result again. An actor of another id does not. The id comes from the actor, never from the document or a body field.
9. Foreign object access responds with `NOT_FOUND` and fixed text, without content or existence hint. A body setting another `tenant_id` ends with `FORBIDDEN`.
10. Both demo principals live in the same SQLite file. T12 checks only logical rejection. That is not customer isolation, not a separate file, not a separate OS account.
11. Approvals bind payload hash, payload revision, rule version, rule hash, and input manifest. Reviewer comes from actor and `reviewer` role. Field `approver_id` in body is rejected. Conflicts stay visible in the artifact; the only allowed edit is `conflict_visible_no_resolution`.
12. `state_version` is the CAS field. `payload_revision` counts content changes. Run row `revision` follows `state_version`. Run identity stays stable. A rule version does not change within a run.
13. Rejections write, when storage is available, a rejection event without business mutation. If that fails, rejection stands and there is no success response. Injected storage failure fully rolls back the running transaction and writes no second event afterward.
14. `testing_fault` is an in-process seam for T11 only. It can only raise an exception. CLI does not set it. Commands cannot enable it via a JSON field.
15. Limits of `material-prep-1`: at most 3 documents, 200000 bytes, 50 claims. Unknown rule fields rejected. Forbidden actions `send`, `http`, `shell`, `model` stay forbidden even if a ruleset removes them from the list.
16. Unknown commands yield `INVALID_TRANSITION`. Missing resolution on `resume` yields `INVALID_INPUT`. Target state of `resume` is state before `block`, never `APPROVED`.

## Not decided by code

Capacity, prices, response times, legal bases, live data, hosting contracts, and production isolation remain open business inputs. I2, I3, and I4 have not started.
