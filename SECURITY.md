# Security policy

## Supported versions

This project is a **v1 candidate (1.0.0rc1)**. It is **not production-ready**. Security fixes are welcome; claims about compliance or certified security posture are not made by this repository.

## Reporting a vulnerability

Please **do not** open a public GitHub issue for security vulnerabilities.

Use [GitHub private vulnerability reporting](https://github.com/buberlo/aaf-gate/security/advisories/new) for this repository. That sends a confidential report to repository administrators.

Include, when possible:

- A description of the issue and potential impact
- Steps to reproduce or a proof of concept
- Affected components (for example `core/`, Hermes adapter, CLI)
- Any suggested mitigation

You should receive an acknowledgement after the report is reviewed. If private vulnerability reporting is not enabled on the repository yet, open a regular issue asking for a private channel and do not include exploit details in the public thread.

## Response expectations

There is no full-time security team. Maintainers and the repository owner will triage reports as capacity allows. Critical issues affecting the gate, audit chain, or policy enforcement logic will be prioritized.
